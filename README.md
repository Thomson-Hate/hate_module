# HATE MODULE
- Бот построен по модульному принципу. Каждый функциональный блок (экономика, модерация, развлечения) вынесен в отдельный модуль — папку внутри modules/. Основной файл bot.py загружает все модули автоматически при запуске.
- Модуль — это самодостаточный пакет Python, который должен содержать файл connector.py с функцией setup(bot). В этой функции модуль регистрирует свои команды, обработчики событий и выполняет инициализацию.

## Преимущества проекта:
- Лёгкое добавление/удаление функционала.
- Изоляция кода: модули не зависят друг от друга (если не предусмотрено иное).
- Возможность автоматической установки зависимостей модуля через requirements.txt внутри модуля.

## 4. Как создать новый модуль
- **Шаг 1. Создайте папку модуля**
*Внутри modules/ создайте папку с названием вашего модуля (например, my_module). Имя должно быть уникальным и отражать функционал.*

- **Шаг 2. Добавьте необходимые файлы**
*Минимально необходим только connector.py. Остальные файлы (commands.py, classes.py и т.д.) создаются по желанию для структурирования кода.*

- **Шаг 3. Реализуйте функцию setup(bot)**
*В файле connector.py обязательно должна быть определена функция setup(bot: commands.Bot). Она будет вызвана при загрузке модуля.*
Пример connector.py:
```python
from nextcord.ext import commands

def setup(bot: commands.Bot):
    # Здесь можно регистрировать команды, события и т.д.
    print("Модуль MyModule загружается")

    # Пример регистрации команды напрямую
    @bot.command(name="hello")
    async def hello(ctx):
        await ctx.send("Привет от модуля MyModule!")
```

- **Шаг 4. (Опционально) Добавьте зависимости модуля**
*Если ваш модуль требует дополнительных библиотек (например, aiohttp, pillow), создайте в папке модуля файл requirements.txt со списком зависимостей. При запуске бота они установятся автоматически (один раз).*

- **Шаг 5. Проверьте работу**
*Запустите bot.py. В консоли должно появиться сообщение о загрузке модуля.*

## 5. API модуля: как взаимодействовать с ботом
## 5.1. Регистрация команд
- Команды можно регистрировать двумя способами:
  
Через декораторы @bot.command() внутри setup
```python
def setup(bot):
    @bot.command(name="ping")
    async def ping(ctx):
        await ctx.send("Pong!")
Через класс Cog (рекомендуется для больших модулей)
Создайте класс, наследующий commands.Cog, и зарегистрируйте его в setup:

python
from nextcord.ext import commands

class MyCog(commands.Cog):
    def __init__(self, bot):
        self.bot = bot

    @commands.command(name="ping")
    async def ping(self, ctx):
        await ctx.send("Pong!")

def setup(bot):
    bot.add_cog(MyCog(bot))
```

## 5.2. Обработка событий
- В когах можно использовать декораторы событий, например @commands.Cog.listener():

```python
class MyCog(commands.Cog):
    @commands.Cog.listener()
    async def on_message(self, message):
        if message.author.bot:
            return
        if "привет" in message.content.lower():
            await message.channel.send("И тебе привет!")
```

## 5.3. Доступ к конфигурации
Модуль может читать глобальные настройки из config.py:
```python
from config import PREFIX

def setup(bot):
    print(f"Префикс бота: {PREFIX}")
```
- Для более гибкой конфигурации можно добавить в config.py словарь с настройками модулей.

## 5.4. Использование базы данных
- Если модулю нужно хранить данные, можно использовать, например, sqlite3 (встроен) или подключить внешнюю БД через зависимости. Рекомендуется создавать файл БД внутри папки модуля.
Пример с sqlite3:
```python
import sqlite3
import os

def setup(bot):
    db_path = os.path.join(os.path.dirname(__file__), "data.db")
    conn = sqlite3.connect(db_path)
    # Создание таблиц и т.д.
    conn.close()
```

## 5.5. Проверка обновлений модуля (опционально)
- Модуль может самостоятельно проверять свою актуальность, например, сравнивая версию с GitHub. Это делается внутри setup (асинхронно, чтобы не блокировать запуск).

## 6. Правила и рекомендации
## 6.1. Именование
Папка модуля: lower_case_with_underscores
Файлы внутри: осмысленные имена, например commands.py, database.py, utils.py
Функция setup: обязательно setup(bot).

## 6.2. Изоляция
- Модуль не должен полагаться на наличие других модулей. Если нужна связь между модулями, используйте общие механизмы (например, базу данных или события через бота).

## 6.3. Обработка ошибок
- В connector.py старайтесь обрабатывать возможные исключения, чтобы при ошибке в одном модуле не падал весь бот.

## 6.4. Зависимости
- Указывайте только необходимые библиотеки в requirements.txt модуля.
- Избегайте конфликтов версий с корневыми зависимостями.

## 6.5. Версионирование модуля (опционально)
- Можно хранить версию модуля в __init__.py или connector.py как переменную __version__ для последующей проверки обновлений.

## 7. Пример простого модуля "Ping"
- Создадим модуль, который добавляет команду !ping.
Структура:
```text
modules/
    ping/
        __init__.py (пустой)
        connector.py
connector.py:
```

```python
from nextcord.ext import commands

def setup(bot: commands.Bot):
    @bot.command(name="ping")
    async def ping(ctx):
        await ctx.send("Pong!")
    print("Модуль Ping загружен")
```
После запуска бота команда !ping будет отвечать "Pong!".

## 8. Начальные библиотеки (requirements.txt)
Создайте в корне проекта файл requirements.txt со следующим минимальным содержимым:
```text
nextcord>=2.6.0
aiohttp>=3.8.0
```
nextcord – основная библиотека для Discord API.
aiohttp – для асинхронных HTTP-запросов (может пригодиться модулям).

При желании можно добавить и другие часто используемые библиотеки, но лучше оставить минимум, чтобы модули сами подтягивали свои зависимости.

**Выполните:**
```bash
python bot.py
```
При первом запуске автоматически установятся все зависимости (корневые и модулей). В консоли вы увидите список загруженных модулей и сообщение о готовности бота.
